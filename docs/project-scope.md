# Паспорт проекта (Вариант А)

## 1. Цель и границы
**Тема:** Трекер поиска работы.
**Задача:** Вести личную воронку поиска работы: подтягивать вакансии, сохранять отклики, менять их статусы и получать уведомления.

**Границы работы:**
- Только backend: CLI для демонстрации и API с OpenAPI. Графический интерфейс не требуется.
- Все моменты времени хранятся в UTC (применение часового пояса — только при выводе).

## 2. Модель данных (Сущности)
В проекте будут следующие основные сущности:
- **User:** владелец данных.
- **SearchFilter:** параметры поиска (запрос, регион, вилка).
- **Vacancy:** вакансия (внешний id, описание, зарплата, статус open/closed).
- **Application:** отклик на вакансию (имеет статус и жизненный цикл).
- **Tag:** теги для вакансий.

**Связи (для шагов с БД):**
- `Vacancy` → `Application` — один ко многим.
- `Vacancy` ↔ `Tag` — многие ко многим.
- Отклики (`Application`) и фильтры принадлежат `User`. Теги личные.

## 3. Обязательный сценарий (MVP)
1. Создать фильтр поиска.
2. Получить вакансии (из локального JSON или фейкового источника).
3. Сохранить отклик на вакансию (создаётся `Application`).
4. Изменить его статус (например, SAVED → APPLIED).
5. Увидеть уведомление о переходе (доменное событие `ApplicationStatusChanged`).

## 4. Состояния и правила переходов
**Статусы отклика (Application):**
- `SAVED` (сохранён)
- `APPLIED` (откликнулся)
- `INTERVIEW` (собеседование)
- `OFFER` (оффер)
- `REJECTED` (отказ)

**Таблица переходов (ALLOWED):**
- `SAVED` → `APPLIED`
- `APPLIED` → `INTERVIEW`, `REJECTED`
- `INTERVIEW` → `OFFER`, `REJECTED`
- `OFFER` → (конечное состояние, переходов нет)
- `REJECTED` → (конечное состояние, переходов нет)

**Правила:**
- Запрещённый переход вызывает доменное исключение (`TransitionError`) и не меняет состояние.
- Повторный переход в то же состояние разрешён (идемпотентность), ничего не меняет.
- Выход из конечных состояний (`OFFER`, `REJECTED`) запрещён.

## 5. Инфраструктурный сценарий
- `httpx` получает вакансии из одного источника (например, hh.ru).
- `async` обходит несколько фильтров параллельно.
- Планировщик (Taskiq/Celery) повторяет сбор вакансий по расписанию.
- Redis кеширует ответ источника с TTL.
- При недоступности источника сохранённые вакансии доступны с отметкой времени обновления.

## 6. Отложенные функции (расширения, НЕ входят в MVP)
- Резюме в PDF.
- Загрузка файлов в S3 (MinIO).
- Текстовые заметки к откликам.
- Календарные напоминания о собеседованиях.
